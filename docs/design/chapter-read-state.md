# 章节已读状态与范围操作

章节的已读状态以 Worker API + D1 为唯一权威。详情页可以直接对已取得的 Source 章节列表标已读或标未读，不必进入阅读器，也不为标记逐章请求 `pages()` 或图片。阅读器实际观察页位与用户明确标记是两种不同输入，共同维护当前章状态，不生成历史事件。

## 协议与状态

`SetChapterRead { chapterKey, read }` 复用作品 mutation 的身份、UUID、精确 revision 和 D1 原子提交路径。现有 `chapter_progress` JSON 保存章节 epoch、`completed` 及可选真实页面锚，无需新表或迁移。`completed` 表示本章已读，可以来自阅读器显式完成或详情人工标记；普通位置保存与 manifest 更新不会清除它，标未读或重新阅读才清除。

- 标已读保留已有真实 current/furthest，没有读取过的章节不构造末页或其它虚假锚点。
- 标未读清除 current/furthest 和 completed，保留新的 epoch 记录，不能删除它而让旧 epoch 重新有效。
- 两种标记都原子提升 epoch，和作品/account revision 一起提交；达到上限明确拒绝。
- 标记不移动漫画 resume，不修改收藏、分类、元数据或书签。读取和标记尚未收藏的作品仍适用。

`ChapterProgressState` 响应允许没有锚点，有 furthest 时必须有 current；真实 `SaveProgress` 仍要求合法的 snapshot/current，与 Source 当前清单的 pageKey 一致。Reader 真正打开无锚状态时，使用实际 manifest 首页建立本地位置并继承已确认 epoch/已读值，不把“无锚”当作从未保存过的 epoch 0。远端标记使旧阅读视图停止写入，保持当前画面，由用户明确重开后再采用服务端状态。

`GET /api/state/manga/:mangaKey/progress` 每页最多 64 项，返回当前保存的章节状态，包括未读 epoch。全分页固定 account revision；发生变化重启有界读取，不拼接不同快照。已成功读取的集合中没有记录才视为未读，读取失败或尚未读取时保留未知状态。客户端只持会话状态，不建立本地业务权威或持久 outbox。

## 详情操作与确认

搜索、书签与已读/未读筛选取交集，显示原序或反序。选择始终使用完整 `SequenceChapter.key`，保留重复标题、重复 URL、空/零/小数章节编号；当前 Source 列表中的缺失条目不猜测重配。可见全选与取消只修改可见项目，隐藏选择保留并提示数量。范围由当前显示顺序的两端点确定，不按章节编号推测范围。

确认清单冻结章节身份、顺序、目标状态和作品 revision，列出所有选中章节，包括筛选后隐藏的目标。逐章串行确认，下一项仅采用上一项 ACK 推进的作品 revision，不从普通刷新抬高旧 CAS。首个失败停止，明确已确认、尚未确认/被拒绝、未开始三类结果；已确认项目不重发。

未确认项目只重试原 UUID、正文与 CAS，成功后显式继续剩余原清单。确定冲突先只读重取完整进度集合，结束旧批次，再重新确认未完成项目；读取不自动重发，不清除不确定请求。暂停等待当前项结束后停止；没有未确认项时可以结束尚未发送的余项。

批次归属当前业务客户端与漫画，重建 repository wrapper 或关闭详情后可以在同会话恢复。身份、服务、仓储或详情失效后，旧窗口永久退役；迟到 ACK 只结算旧草稿，不续发、不关闭新路由、不修改新身份。系统返回和按钮共用关闭结果，保留未完成选择。重开详情后的 Source 章节列表若已变化，旧批次仍保留原清单和 key；返回的新选择只保留当前列表仍存在的 key，明确提示未匹配数量，不自动映射到其它章节。其它未确认操作不能被标记入口隐式重发。

实施状态见 [P1](../plan/p1-library-and-progress.md) 和 [P2](../plan/p2-sync.md)。协议、真实 D1、组件、独立客户端和设备验收分别计证据，不能用受控 supplier 证明完整跨端功能。
