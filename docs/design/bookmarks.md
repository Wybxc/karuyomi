# 章节书签

书签是作品内的章节标记，按现有 `ChapterSequence` 生成的章节键定位。详情章节列表支持标记、移除与仅书签筛选，阅读页支持当前章的同一操作。不按标题、章节号或旧列表序号猜测对应章节；当前 Source 列表中已消失的章节保留记录并提示未匹配。任意页锚和笔记不属于本次章节书签功能。

## 服务端权威与协议

Worker API + D1 是唯一业务权威，Web/iOS/Android 共用 `business.proto` 生成的类型与标准 ProtoJSON。`setBookmark` 复用作品 mutation 的身份、revision、UUID 与 nonce gate；书签行、作品 revision、account revision 和幂等响应在同一 D1 batch 提交。仅存已标记的章节行，不产生历史事件。未收藏、未写进度的作品也可以标记；取消收藏、更新资料和重新阅读不会删除书签，也不因书签修改而改变 resume、当前/最远进度或 epoch。

`GET /api/state/manga/:mangaKey/bookmarks` 独立分页读取，每页最多 64 项；后续页固定 account revision，变化后重新读取，不能拼接不同快照。查询当前章时，既有作品状态接口还返回该章的明确布尔状态，包括未标记。书架响应不携带整套书签。

## 客户端确认与恢复

详情和阅读页共用身份绑定的业务客户端及作品写队列。界面仅在服务端确认后改变标记。首次写入前，只有可证明是本会话已确认写入造成的 revision 变化可以推进 CAS，避免正常阅读进度使书签无法使用；远端变化仍明确冲突。首次发送后 UUID、正文和 CAS 永久固定，丢响应只由用户明确重试原操作，其它收藏、进度或新书签操作不能隐式重发它。

重试收到的幂等成功仅说明原操作发生过，客户端必须重新读取当前章，不能把旧成功当成当前已标记，更不能使已被其它端删除的书签复活。冲突后重新读取完整集合并确认当前状态，再编辑；读取不会自动提交命令。未确认草稿只保存在当前会话，身份或服务变化使旧页面失效，迟到结果不能更新新的页面。Access 恢复采用原身份绑定客户端，阅读页重新读取确认视图；已加载的阅读不依赖书签请求成功。

实施状态见 [P2](../plan/p2-sync.md)，实际验证范围见[书签记录](../verification/bookmarks.md)。
