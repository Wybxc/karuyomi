# 书架批量操作

书架在已确认的服务端视图上提供多选、添加分类、移出分类和移出书架。继续使用现有单漫画 API，逐项取得 D1 权威结果；批次不是服务端原子事务，也不建立本地业务数据库或持久待提交队列。

## 选择与确认

选择使用稳定 `mangaKey`。搜索、分类筛选和显示排序只改变可见投影，不静默改变已选清单；“全选当前显示”并入可见项目，“取消当前显示”只移除可见项目，页面同时显示总选中与隐藏选中数量。选择模式中点击漫画切换选择，退出选择后才恢复打开详情与单项分类入口。

确认窗口列出全部目标的标题与来源，包含筛选后不可见的已选作品。首次确认前可以选择目标分类；确认后冻结当前 `LibraryView`、每本漫画 revision、分类目录 revision 和逐本目标集合，不能在重试期间悄悄采用后来读取的 revision。

添加分类取各漫画原关联与选定分类的并集；移出分类取差集，保留其它关联。移出书架只提交 `favorite=false`，不附旧元数据，也不清除分类、进度和书签。即使某本原关联已经满足目标，仍按同一确认路径提交并取得 ACK；不靠客户端推断该项已经确认。

## 执行与恢复

按冻结清单串行发送，收到该项成功确认才继续。首个失败立即停止，分别显示已确认、未确认或已拒绝、尚未发送的项目。已确认项不会随整批重试；未确认项只允许原 mutation ID、正文及 CAS 重试，成功后由用户明确继续剩余原清单。

确定的 revision/目录冲突或不可重试拒绝必须先只读刷新并结束旧批次，再依据新视图重新确认未完成项目。刷新不发送修改、不抬高旧 CAS；另一项未确认操作也不能由批次入口隐式重发。数据客户端的精确模式检查固定 revision 与目标字段，直到确认快照更新成功才释放原 pending，避免 ACK 后补读失败丢失原请求身份。

暂停不会撤回已经发送的请求；等待当前项结束后停止，后续项目不发送。所有已尝试项均已确认、只余未开始项目时，可以结束剩余操作并保留这些漫画供重新选择；尚未确认的请求不能借此丢弃。批次只驻留当前 `BusinessStateClient` 会话，关闭窗口后提供恢复入口，同一客户端重建 repository wrapper 仍能找回原批次。单项分类编辑与批次互斥；客户端进程结束后从服务端重读已经确认的结果，不承诺恢复未确认草稿。

## 生命周期与边界

身份、服务、repository 或宿主页面失效后，旧窗口永久退役。迟到 ACK 可以结算旧草稿，但不能发送下一项、关闭新路由或修改新身份的选择。恢复必须由当前有效页面重新打开；读写前后都检查当前会话。UI 负责路由与身份判定，执行层只依赖数据仓储及有效性回调，不反向依赖分类弹窗。

列表仍使用已有有界书架快照，不另设更小的任意多选上限。这里的客户端确认流程不能代替真实多客户端、生产 Access、设备交互与并发验收；实际证据维护在验证文档，后续范围见 [P1](../plan/p1-library-and-progress.md) 与 [P2](../plan/p2-sync.md)。
