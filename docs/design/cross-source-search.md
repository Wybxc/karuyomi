# 能力提示与有界跨源搜索

跨源搜索复用已确认的账户安装意图、静态目录、Source 设置和正式运行时。它不创建另一套扩展清单或服务端搜索任务，也不把搜索结果写入书架。实施状态见[计划](../plan/cross-source-search.md)，上级范围见 [P3](../plan/p3-extensions-and-migration.md)。

## 候选与界面

浏览页提供独立“跨源搜索”入口。候选来自当前账户已经确认安装、启用、所属仓库仍登记、静态构建仍匹配且网络政策已登记的 Source；刷新候选只读，不安装、升级、换仓或执行扩展来枚举名称。候选保留 `catalogUrl/repoId/package/buildId/bundleSha256/sourceId`，同名、同 Source ID 或同包跨仓记录不能合并成另一来源。

默认不选择任何 Source。用户按名称或扩展包查找、按语言筛选并明确勾选；候选列表分组显示，不截断未显示的候选。开始时冻结搜索词和本轮选择，各 Source 独立显示等待、执行、结果、错误及停止状态。一个慢源或普通 Source 错误不清除其它源的结果。

首轮只请求第一页。下一页和失败重试均由用户逐源触发，沿用该源冻结的搜索词和精确来源；不自动滚动翻页、自动重试或回退到热门。本轮不叠加普通浏览页的自定义筛选状态。结果按源展示，不按作品标题跨源去重，不直接请求原缩略图 URL。

## 两个物理执行槽

正式控制协议区分 `foreground` 与 `search` 两个运行槽，请求、响应和事件都核对槽身份。每槽有独立的 manager、runtime session、generation 和操作队列；一个槽的取消、重建或迟到响应不能清空另一槽。Web/Native 共用同一合同，容器级丢失与槽内失败明确区分。

本里程碑采用最直接的独占方式：只有无活动阅读资源、无前台操作且没有其它搜索持有槽时才能开始搜索。首次实际执行前精确关闭当前浏览 Source，并等待关闭确认；随后搜索独占这两个物理槽。它不在阅读期间后台搜索，也不借用阅读中的同包 Worker。普通浏览与阅读在搜索清理完成前不能并发取得这些槽。

调度直接使用锁定的 `pool`，全局并发最多 2。按已确认业务客户端的服务/账户身份、catalog URL、repoId 和 package 分组；一个包队列只占一个槽，同包多个 Source 串行执行并复用已打开的包。Source 可变存储仍使用完整的应用 origin、subject、catalog URL、repoId、package 和 storage schema namespace；精确安装门禁防止同包不同构建或来源同时写入。跨包可以占用第二槽，不能每安装一包就常驻一个 Worker。

取得实际槽后才从“等待执行”切换为“正在搜索”。每包队列完成后关闭其运行时；全部包关闭确认且没有待恢复的槽后，才交还主浏览所有权。后续手动分页可以重新取得槽，不因此保持常驻扩展。

## 打开与调用门禁

每次 Source 执行均重新检查原账户 client、当前 confirmed 安装、enabled、仓库登记、精确 build/hash、manifest、Source ID 和网络政策。Source 设置沿用原来源的已确认 bootstrap，未处理的设置请求阻止执行；搜索不隐式重放设置保存，也不跨仓继承当前会话敏感值。

点击结果先停止本轮任务，等待两槽清理与主线所有权归还，再重新核对该结果的原精确来源。通过主 Catalog 的正式打开入口选择 Source，不额外读取热门，然后调用正式 details/chapters 并进入既有详情页。缺包、停用、下架、换仓或 hash 改变均明确失败，不偷偷打开另一来源的同名作品。

搜索页绑定点击入口时创建的业务 client，不能因普通 Source 切换而换绑账户。详情导航前和惰性 route builder 再检查原 client 与当前 Source 引用；身份改变、Access 失效、服务替换或页面退休后的迟到结果不能继续请求或导航。

## 取消、关闭与失败

新查询先停止旧轮；逐源停止、停止全部、切入后台、离页及进入详情都走正式取消/清理链。回到前台或从详情返回不自动重放搜索。队列中的取消阻止之后取得槽或运行扩展；运行中的取消使用原 requestId/generation，必要时只重建本搜索独占的槽。

精确 `closeBuild(buildId,generation)` 需要关闭 ACK 和 namespace/产物引用释放；若关闭或取消无法确认，可以使用该槽的显式 reset ACK 证明物理回收。reset 是恢复清理，不是 Source 操作重试，也不能描述为已收到扩展 shutdown ACK。不得用整容器重建影响另一槽，或用提前完成 Future 冒充资源已经释放。

关闭与 reset 均未确认时保留待清理槽和占用状态，禁止交还主线或继续新任务。UI 单独显示停止/清理失败，允许显式重试；正常返回必须等待 `close()` 成功，失败留在搜索页。身份/服务退休不可自动复活，清理重试不恢复旧查询。旧请求的迟到取消失败不得覆盖后来已确认的全局停止。

## 限额

| 边界         | 当前上限与行为                                            |
| ------------ | --------------------------------------------------------- |
| 本轮选择     | 1–32 个 Source；不自动全选或截取前 32 个                  |
| 搜索词       | trim 后非空，最多 500 个 UTF-16 code unit；空词不回退热门 |
| 物理槽       | 同时最多 2 个，同包前台 RPC 串行                          |
| Source 请求  | 沿用正式 30 秒操作超时、取消与协议正文预算                |
| 单页响应     | 最多 200 个作品，超出拒绝整页                             |
| 每源累计结果 | 最多 200 项                                               |
| 本轮累计结果 | 所有 Source 合计最多 1000 项                              |
| 翻页         | 手动逐源触发；页号沿用正式有界校验                        |

累计预算由页面控制器维护。若整页加入后会越界，保留先前结果并明确要求缩小查询或选择范围，不静默截断该页、不隐式分批追加。达到上限时明确说明仍可能存在后续结果。

## 能力提示的事实边界

本次新增的明确提示来自实际 `SourceInfo.supportsLatest=false`：该源不提供最新列表，用户仍可使用热门或搜索。静态 `CatalogSource` 的 ID、名称和语言用于选择，不证明在线能力。`RuntimeSession.capabilities` 只表示宿主通道，实际 `unsupportedCapability` 仍由当前操作错误呈现。

不建设人工维护的逐源能力矩阵，也不为已有可用菜单重复增加“可用”徽章。不能从普通 403、网络失败、编译成功、manifest 一致或脚本不支持推断“需登录”“需验证码”或“可读”。登录、验证码、脚本和完整阅读能力只能按实际 Source、构建与平台证据声明；未实测扩展继续保持 `compiled_unverified` / `runtimeReady=false` 的构建状态。
