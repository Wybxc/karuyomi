# 详情章节浏览

详情页以 Source 已返回的完整章节列表为输入，搜索、筛选和显示排序只改变当前页面的投影。它们不重新调用 Source、不另存章节权威，也不把过滤后的列表交给阅读器作为完整目录。

## 章节身份与显示顺序

`ChapterSequence` 保留每次出现及其原始 `sourceIndex`。唯一 URL 使用作品/Source 范围内的稳定键；重复 URL 使用章节列表快照与 occurrence 键。相同标题、相同 URL、缺失/零/小数编号均不能成为去重或推测排序的理由。

页面提供来源顺序及反向来源顺序，不按章节号或上传时间重排。显示名、扫描组、章节号和来源序号帮助区分重复条目，原始 Chapter DTO 保持不变。用户点击可见条目后，依其原始索引与键取得原 Chapter，不能把显示索引当成源索引。

## 搜索与筛选

搜索章节名、扫描组和显示章节号，忽略首尾空白及文本大小写，和“仅书签”取交集；清空查询恢复当前筛选下的列表。显示命中数量和无匹配状态，Source 本身返回空列表与搜索无命中分别提示。书签尚未确认时不把未知状态当成已确认未标记。

这些是当前详情会话的浏览状态，不作为一份独立的跨端业务记录持久化。阅读器使用完整 `ChapterSequence`，其来源顺序继续由现有服务端进度链路管理；从详情明确选择的顺序进入阅读后适用；详情尚未确认 resume 且用户未选顺序时，保留阅读器读取服务端顺序的路径，不能强传页面默认值。不能因筛选而改变上一章/下一章的邻接含义。“继续阅读”仍定位服务端 resume 的原章节，而不是首个搜索结果。

实施状态维护在 [P1](../plan/p1-library-and-progress.md)，实际检查和平台限制另记验证文档。
