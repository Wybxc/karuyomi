# 扩展管理

## 目标与状态

**状态：未实现，本文是只读代码核对后的实施计划。** 构建加载、静态分发和包/Source 选择已有基础，但不等于账户安装、启用、更新或卸载能力已经完成。上级范围见 [P3 扩展管理与源迁移](p3-extensions-and-migration.md)，静态发布约束见[工程计划](engineering-and-release.md)。

目标是让同一身份在 Web、iOS、Android 使用同一份账户扩展清单，区分账户已确认的使用意图、本机准备情况和正在运行的精确构建。安装不执行扩展，更新由用户明确发起，切换前完成运行槽关闭，卸载后能真实清理不再使用的扩展产物副本。

服务器继续仅提供每包最新可用构建，不增加历史版本、旧协议兼容或隐式回退。本文不启动 AOT、改变发布 checkpoint，也不将候选缓存接法写成已具备能力。

## 权威与状态边界

- **D1 账户意图**：已添加的扩展、稳定的仓库与包身份、启用状态，以及用户明确选择的当前 build。复用身份绑定的全局设置、CAS、原 mutation UUID 和请求重试；所有全局设置编辑必须保留主题、阅读偏好、收藏源及扩展清单。最终字段与限额通过正式 Protobuf 合同确定。
- **本机准备状态**：未下载、准备中、已验证可用、下载或材料错误、缓存占用与清理结果。它们是可丢弃状态，不作为第二份业务权威，不承诺另一台设备已经下载成功。
- **当前运行状态**：精确的 buildId、generation、Source、阅读资源与 namespace 所有权。收到账户更新不静默替换正在执行的构建；切换在明确操作边界进行。
- **构建来源**：Static Assets 的当前索引与清单是产物分发权威。共享 materials 仍作为 Web 静态资源或 Native 内置资源，不按扩展重复缓存或通过网络回退补齐 Native 材料。

账户选择的旧构建可能已不可获取。现有注册流程会删除同包其它 build 的网络登记，HTTP 桥按 `X-Runtime-Build` 查询登记；缺失返回 `404 build_not_found`。因此，即使本地还保留旧代码，也不能保证该构建继续联网。界面应将“当前选择已下架，请手动更新”与 Access 的登录失效或权限拒绝分开，不把缓存命中显示为在线可用保证。

## 当前基础与真实缺口

1. `VerifiedLoader` 已实现当前索引、manifest、有界下载与 gzip/内容验证；扩展正文使用浏览器或 WebView HTTP 缓存。尚无应用可枚举、按构建删除、报告占用并复用已验证结果的受管产物缓存。
2. `SourceRuntimeManager` 已有单执行槽、代次失效、请求取消和 namespace Web Lock。不同 build 共享同身份、仓库、包及 storage schema 对应的可变 namespace；新槽会等待自身旧锁释放，跨标签页竞争会明确失败。
3. `open` 替换旧槽和 `rebuild` 主要是强制失效；`rebuild` 不提供等待 namespace 释放的独立 ACK。永久 `dispose` 才尝试安静关闭并等待锁释放，但不能直接作为可继续使用的卸载或更新操作。
4. OkHttp 缓存桥的 clear 只覆盖其目录，文件桥 close 只释放所有权。二者均不是扩展 JS 缓存清理，也没有应用级单 namespace 删除入口；不能全清 IndexedDB 或 WebView 数据来冒充单扩展卸载。
5. Flutter 正式浏览、收藏源快捷打开和书架打开目前按已读取静态索引选择构建。它们尚未共同遵守账户安装、启用与精确 build 选择，也没有独立的“不执行扩展的本机准备”流程。

## 实施任务

### 账户清单与仓库接入

- 增加有界、稳定身份唯一的账户扩展记录，明确安装成员关系、启用状态及精确构建选择；定义缺包、下架构建和未知仓库的保留与展示规则，不在只读刷新时自动删除或换版。
- 接入现有全局设置读写与确认流：修改以最初 CAS 为准；未知 ACK 只能显式重试原 UUID/body；冲突后只读重取并由用户重新确认。任意全局 pending 不得被扩展操作覆盖或隐式重放。
- **保留 P3 的仓库添加完整待办。** 额外仓库如何登记、验证、更新与移除，以及如何接入既定 Static Assets 权威和 Source 网络政策，仍须落实设计。不得把默认静态索引已有连接悄悄改称仓库添加已经完成，也不得将本里程碑永久缩为只有默认仓库。
- 明确额外仓库和包身份冲突、构建来源验证、允许的网络目标及无 AOT 产物的状态；没有当前可用构建时显示待构建或不支持，不从客户端启动远程编译。

### 本机准备与受管缓存

- 增加不创建 Source Worker、不执行扩展、不调用 Source 的准备操作，完成当前清单解析、下载、有界解压、验证和本机缓存提交。安装不得复用“再次打开构建”来假装完成准备。
- 实现有界的构建元数据与产物引用、取消、占用查询及按引用清理。成熟库 `idb` 是可复用的候选接法，尚未接入或实测；具体存储选择应支持实际 Web 与 Native 宿主。
- 在下载边界完成各字节域的完整性验证；后续本地处理复用已验证结果，不反复读取计算同一份字节。缓存丢失只触发重新准备当前可获取构建，不恢复独立业务数据库或持久 outbox。
- 清理不再使用的旧产物时保留当前运行引用，待资源释放后再删。安装副本、共享 materials、Source HTTP 缓存和 Source 数据采用明确的不同范围。

### 运行槽关闭与切换

- 增加可复用、带预期 build/generation 的关闭操作，停止接收新调用，处理排队和正在执行的任务，完成阅读 provider、图片资源及可变存储所有权收尾，等待 namespace 锁释放后返回明确 ACK。
- 复用已有取消的真实语义：正在执行的 Source 请求取消可能回收整代；不要承诺取消后原槽仍可继续。迟到关闭或 ACK 不得影响新槽或新身份。
- 处理存储竞争、超时和释放失败，保留准确状态及显式恢复入口；不把发出 terminate/rebuild 当作已经安全排空或缓存已清理。

### 正式管理与打开入口

- 提供可操作的账户扩展列表和仓库入口，分别显示账户确认状态、本机准备状态、当前使用构建、最新可用构建与具体错误。
- 安装和更新先准备候选，再确认账户选择；候选准备或 CAS 失败不得伪报已安装/已更新，候选缓存仍只是可丢弃副本。检查更新仅重读当前索引，不自动写入账户选择。
- 启用/停用由 D1 确认驱动；浏览、收藏源和书架的正式打开路径共同检查清单，不能绕开停用状态或静默换到索引最新版。其它设备按既定只读同步边界收敛，已加载内容与后续调用的处理须明确。
- 卸载确认账户移除后关闭对应槽、清理本机扩展副本，分别显示账户结果与清理结果；清理失败可重试。卸载保留书架、分类、进度、书签、收藏源及 Source 数据，不顺带执行来源数据抹除。
- 如未来提供单独的“清除来源数据”，须在安全关闭和取得相应 namespace 所有权后处理，不混入普通卸载成功语义。

## 验收条件

- 两个独立客户端在同一身份下读回相同的扩展清单、启用状态与精确构建选择；其中一端缓存为空时准确显示本机未准备，不伪报另一端已安装可用。
- 安装准备不创建 Source Worker 或产生 Source 请求；成功确认后正式打开使用所选构建。下载中断、材料缺失、错误响应、CAS 冲突及 ACK 丢失有准确结果与显式恢复，原请求不会被其它全局设置编辑覆盖。
- 手动检查能发现最新版；用户确认更新前不替换当前构建。旧清单或网络登记下架时明确显示不可获取/`build_not_found`，不误导为 Access 失效、不回退旧协议或自动选择其它版本。
- 更新、停用和卸载在活动请求、阅读资源及 namespace 竞争下，能够验证关闭 ACK、迟到结果丢弃和新旧槽隔离；未释放的槽不得宣称清理完成。
- 本机缓存占用与删除有真实证据；旧副本在引用释放后删除，共享材料与其它包不受误删。卸载后业务状态及 Source 数据保留，另一端读回账户移除并执行本机收敛。
- 额外仓库添加、身份冲突、网络政策接入和缺失 AOT 的可见状态分别有正式入口与证据，不以默认仓库浏览替代完整仓库能力。
- 记录实际 Web、iOS、Android 的通过层级。组件、模拟 supplier、下载验证或构建成功不得写成真实 Source、独立客户端同步或真机验收已经通过。
