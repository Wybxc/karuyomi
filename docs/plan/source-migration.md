# 源迁移

## 目标与状态

**状态：正式功能与工程检查通过，真实 Web 与 iOS 模拟器的顺序迁移及独立读回通过。** 正式迁移协议、Worker API + D1 原子写、Flutter 数据层、书架/详情入口与向导已接入。真实 Web 发现无搜索结果的 Source 无法选作品，补齐目标源热门与分页后，xkcd 英文到中文的显式映射、确认和新文档读回通过；[iOS 模拟器](../verification/source-migration.md#ios-模拟器正式源迁移与新进程读回)同样通过真实向导和新进程读回。Android、混合平台、故障、生产和真机门继续推进。上级范围见 [P3](p3-extensions-and-migration.md)，合同见[设计](../design/source-migration.md)，实际结果统一见[验证](../verification/source-migration.md)。

完成“选择已安装的目标 Source → 搜索或热门列表/分页 → 确认目标作品 → 只读预览一对一章节映射 → 独立确认 → 原子补充目标收藏、分类、已读/书签”流程。原条目始终保留，跨源不复制页面位置、resume、自定义封面、阅读顺序或原 epoch；目标已有业务与章节状态保留。

## 当前实现

- `business.proto` 的 `migrateFrom` 沿既有 mutation 路由传目标 CAS、源 CAS、分类目录 CAS、目标 metadata 和至多 256 组明确映射，128KiB 请求预算不扩大。TS/Dart 生成模型与双端语义校验已接入。
- D1 同一 batch 以三 CAS、UUID/hash/attempt_nonce gate 实现目标收藏、分类并集及仅缺失的正向已读/书签增补；目标已有 progress 整行保留，新增已读采用 epoch 1 且没有页锚。真实 D1 定向测试已覆盖竞争、幂等与故障回滚。
- 数据层使用不可变预览、完整分页与 revision 核对，待确认操作占用双作品/分类；原 body/UUID/CAS 只显式重试，旧 ACK 不能回退当前状态。页面失效后的读取与排队写入受生命周期检查约束，受控客户端回归与独立集中检查通过。
- 书架/详情入口与正式 Source 搜索、详情、章节预览和独立确认已接线，向导支持手动一对一映射、完整章节分页及明确仅迁收藏/分类；原源故障、映射调整、超限、独立确认及路由身份变更均有回归；组件通过不替代实际平台验收。

## 验收条件

- 未独立确认前零迁移写入，任一查询失败或资料变动不能给出可提交的假完整预览；原 Source 不可用须明确选择只迁收藏/分类。
- 模糊、重复或多重认领章节不自动匹配；零章、小数、缺号、扫描组及重复 URL 身份保留。全表可查、任意目标可手动选择，单次选择超限明确拒绝，不截断或隐式拆批。
- 最终写入符合显示的目标与三 CAS。源或目录发生竞争、目标变动或 SQL 失败均无部分写入，原作品不改；目标已有 progress、书签、分类、封面和续读状态保留，仅增补确认的缺失正向标记。
- ACK 未知只显式重试原请求；刷新/重进页面不重放。拒绝后须显式处理草稿再重读预览；旧幂等 ACK 不回退另一客户端的新状态。源、目标和分类的其它新写不能越过 pending。
- 页面或身份失效后不再发后续读取或新写、不导航；已发写的确认收尾不污染新身份。未确认会话草稿不伪报保存或承诺进程关闭后恢复。
- 工程、受控组件、实际 Source、独立客户端、生产 Access 与 Native/真机分别有真实环境证据；不以测试总数或 AOT 完整性替代这些层级。
