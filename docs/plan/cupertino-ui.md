# 全端 Cupertino UI 迁移

## 目标与状态

状态：进行中。2026-11-13 用户确定 Web / iOS / Android 全端统一 Cupertino，维护一套界面实现。按一个完整版本集中切换，开发提交按可审阅范围拆分，交付包含全部正式入口、测试界面和诊断页。[设计决策](../design/cupertino-ui.md)维护主题、控件与生命周期依据；本文件维护待办和验收。

沿用已交付的 Flutter 3.50.0 / Dart 3.14.0、Riverpod generator、Hooks 与 riverpod_lint。Worker API + D1 仍是唯一业务权威，CAS、幂等提交、服务端确认、身份隔离、未确认草稿、generation、取消和关闭 ACK 继续作为正确性要求。Mihon 继续提供信息架构参考，[浏览与扩展流程](../design/extension-browse-ui-flow.md)保留业务状态及最小必要信息。

当前应用壳、全部业务界面、阅读器、诊断和原生 Access 页已完成代码迁移，完整 CI / Web 构建与隔离浏览器验收通过，待生产发布及验收。书架分类改为范围选择，章节筛选改为分段选择，源偏好单选删除重复确认层，长选项与章节映射复用可搜索选择页；这些流程使用官方控件，无需增加第三方 UI 包。工程与 Cupertino 运行验收按下述门槛逐项记录。原生现场验证继续按用户要求停止，实现覆盖原生共享代码与 Access 页面，但不能据此声称 iOS/Android 实际验收完成。

## 集中实施顺序

以下为可审阅开发提交，不是三个独立上线阶段。集中完成后通过既有主线 CI 自动发布；不长期维护混搭页面、双主题分支或旧界面回退层。

- [x] 用正式 pub 命令将 `cupertino_ui: 1.1.6` 设为直接精确依赖，固定 `cupertino_icons: 1.0.9`，提交对应 lock。沿用当前 SDK，不同时升级无关依赖。
- [x] 根改为 `CupertinoApp`、官方 Cupertino 本地化与动态颜色；把已确认 `AppTheme` 映射为系统/浅色/深色 brightness，删除仅为 Material 服务的主题转换和配置。

本机仅做轻量编辑、生成、分析及必要回归，低优先级单并发，不开常驻 generator watch 或模拟器。工程入口使用固定 SDK：`pnpm flutter:generate:check`、`pnpm generate:check`、`pnpm format`、`pnpm format:check`、`pnpm check:dependencies`、`pnpm flutter:check --concurrency=1`；完整 `pnpm check` / `pnpm build` 交给 CI。

按现有[主线 CI 自动发布](../DEPLOYMENT.md)交付，生产核对同一构建的入口、资源、Access、真实阅读、保存及新文档续读。原生现场和可选性能测量不阻塞已通过门槛的 Web 交付，未执行项保持待验。UI 迁移复用现有扩展产物，不触发全量 AOT；后续若确有 AOT 输入变化，仅使用获准的 clab，不使用 pku-dasys，远端查询采用较长周期。
