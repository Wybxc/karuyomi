# P1 多端书架、阅读设置与进度

## 目标与状态

在 P0 真实阅读链路上完成可多端日用的书架、详情、阅读设置、进度与错误恢复。**多端同步是首要设计目标**：书架、分类、进度、书签和非敏感设置通过 Worker API 读写，以 D1 为唯一权威来源。P1 与前移的 [P2](p2-sync.md) 共同交付，先证明两个客户端共享收藏和继续阅读，再完善全部外围 UI。

状态：**进行中，收藏与进度已切换到 Worker API + D1，测试身份下 Web↔iOS、Web↔Android、iOS↔Android 的基础书架读回与双向非默认页续读已通过**，见[Web/iOS 证据](../verification/native-server-state.md)和[Android 配对证据](../verification/android-server-state.md)。本地业务 SQLite、持久化依赖和数据库 Web 资产已移除；书架/进度共享服务端 revision 与确认路径。实际双 Web 的手动刷新、远端重置、旧视图停止写入/写冲突和明确重开已通过[分项](../verification/concurrent-server-state.md)；同时写竞争、自动前台重取、故障恢复、生产 Access、真机、Web↔Native 分类、Android 初始化可靠性、章节书签的独立客户端验收、三项同步设置的独立客户端验收、其余阅读设置及完整日用流程仍待实施或验收，不能认定完整 P1 通过。

## 已有基础与可复用证据

- Flutter 浏览已有构建/Source 选择、热门/最新/搜索分页、详情和章节入口；历史本地书架已验证详情收藏、搜索/排序及经详情继续阅读。完整 Source Manga 快照、稳定作品键、当前静态索引定位和取消收藏保留进度的业务语义可复用，见[本地书架验证](../verification/p1-local-library.md)。本地 SQLite 持久化测试只证明旧实现行为，不替代 D1 或跨端验收。
- 独立 Dart 阅读核心已有逻辑锚、布局/方向、缩放和有界资源调度；当前/最远位置、显式完成、重新阅读 epoch、保存失败提示和节流机制已有实现。Web 真实 Arknights 关标签页恢复及双端模拟器原 xkcd 进程重启的历史分项见[Web 产品进度](../verification/reader-progress-web.md)和[本地进度记录](../verification/local-progress.md)；这些结果保留原输入和范围。
- 单 hostname、Access/API、D1 网络策略工程入口与 Protobuf/Buf 控制协议已经存在。收藏、元数据、分章进度、resume 与幂等结果已建立 D1 表、双端生成业务协议和正式 API；工程和真实多端证据仍分别验收。

## 待办与实施顺序

1. **与 P2 共用服务端业务底座。** 漫画、收藏、章节引用及进度/阅读位置的 `.proto` + Buf 双端协议、D1 模型、身份归属、mutation ID、revision 和冲突响应已接入；分类/多分类协议、D1 API 和 Flutter 数据层已接入，管理、筛选与多关联 UI 已接入并通过[真实双 Web 分项](../verification/category-ui-sync.md)，双 iOS 与 iOS↔Android 分类顺序门也已通过，Web↔Native 分类和 Android 初始化可靠性继续按 [P2](p2-sync.md) 推进；章节书签协议、D1 与正式详情/阅读入口已接入（见[记录](../verification/bookmarks.md)），独立客户端门待验；现有三项非敏感设置的协议、D1 与 API 已接入，客户端和集中检查继续推进，见[设置记录](../verification/reader-settings.md)。Worker 校验 Access 身份后读写 D1，客户端经同一 API 取得权威状态；具体幂等、并发和恢复门以 [P2](p2-sync.md) 为准。
2. **先验收收藏和继续阅读的双端闭环。** 现有书架与阅读进度已接到服务端读写确认路径，继续验证 A 端收藏、B 端读回并阅读、A 端恢复 B 已确认的位置。客户端仅保留当前页面内存状态和当前会话未确认草稿；本地权威数据库读写已移除，不增加旧数据导入、双写或兼容层。断网/Access 失效时保留已加载阅读、显示未保存状态并允许重试，不承诺应用关闭后保留未确认修改。
3. 完成分类排序、书架搜索/过滤/批量操作、自定义封面及继续阅读 UI；每项采用同一 D1 权威状态和跨端合同。初版读取当前状态或有界分页，页面进入/恢复前台/重连时重取；可在已读取结果中即时搜索，不另存一份可独立修改的本地书架。未读数只使用主动取得的章节列表，不触发全书架查更新。封面走正式图片/私有对象通道，不用原图 URL 绕过插件处理。
4. 详情章节名/扫描组/显示编号搜索、来源原序/反序、书签组合筛选和重复项说明已接入正式 UI，工程证据见[章节浏览](../verification/chapter-browsing.md)。继续完善范围已读/标未读操作；保留原 Source URL、稳定 ID、空/小数章节编号及来源顺序，不按标题全局去重。范围已读、标未读和重读也必须由服务端确认并在另一端读回。
5. 完善全局与漫画覆盖阅读设置：分页/连续/Webtoon、单双页、方向、适宽/适高、裁白、背景/应用内亮度、点击区与键盘；区分需要跨端共享的偏好和平台专属临时状态。本轮先同步已有的全局主题、四种阅读模式及 AUTO/SINGLE/DOUBLE 页组，阅读字段可逐漫画覆盖/继承；协议与服务端已接入，客户端和集中检查继续推进，见[设计](../design/reader-settings.md)与[记录](../verification/reader-settings.md)。适宽/适高、裁白、背景/亮度和可配置输入继续保留未实现，不能以这三项代替完整阅读设置。设置模型随功能一起通过服务端保存与跨端读回，能力不足时仍保留正常阅读。
6. **验收服务端逻辑锚与跨端阅读语义。** `chapterKey + pageKey + manifestVersion + pageIndexHint + normalizedOffset` 等逻辑锚已接到 D1，分开保存当前回看位置、同 epoch 最远进度和显式完成状态；继续验证跨端与并发行为，跨 manifest 不直接比较旧序号。复用现有 600 ms trailing debounce、2 秒最长等待和切章/退出/后台尽力提交机制，服务端返回确认才显示已保存。末页真实显示后，显式“读完本章”或“下一章”才标完成；重新阅读由服务端原子提升 epoch，旧提交不能覆盖它。保持当前阅读位置，不因另一设备更新而强制跳页；不依赖 unload 一定成功，不生成时间线事件。
7. 完成网络错误、验证、Source 登录与 Access 失效的独立状态。API 的幂等业务重试与 Source 请求副作用分别处理；有限重试安全读取，取消无用请求，不盲目重发 Source POST。Web 更新前尽力提交位置并明确失败，阅读中不强制重载；身份/服务切换后旧草稿和迟到结果不能写入新身份。
8. 对实际候选 Source 必需的远程脚本提供局部适配、最小回调与超时/存储边界；未实现路径明确受限，不把同源 `eval` 称为受限沙箱。该工作不阻塞已经可读 Source 的基础多端功能实现。

## 验收

- 同一部署与身份在 Web、iOS、Android 通过相同 Worker API 共享收藏、分类、书签、设置和阅读位置；至少两个独立客户端实际读写确认，具体平台组合和并发矩阵见 [P2](p2-sync.md)。服务端已确认状态在新客户端和重启后从 D1 恢复。
- “A 端收藏 → B 端书架 → 详情取章 → 完整阅读 → 服务端确认进度 → A 端继续阅读”形成日用闭环；当前/最远进度、epoch、删除与设置冲突有明确结果。只在单端恢复或只通过 SQLite 测试不能通过本项。
- 网络失败可重试、取消和恢复，不串身份或结果；云端请求失败仍可阅读已经加载的页面，UI 准确区分未保存与已确认状态。Source 文件/cache、扩展缓存、图片资源与业务状态归属明确分开。
- 手机触控、桌面键盘、平板分屏和阅读更新恢复通过实际环境验证；裁白/布局改变后仍定位同一原图锚点。
- Access 登录不成为应用内账号模块；不引入自动更新、离线下载、持久离线操作队列、历史统计、tracker、本地漫画或备份。

完整 P1 必须包含 P2 的基本多端状态门；增量日志、cursor、DO 通知等优化在实测需要后另行安排，不以这些优化延后基础跨端交付。
