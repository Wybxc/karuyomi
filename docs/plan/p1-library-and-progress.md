# P1 多端书架、阅读设置与进度

## 目标与状态

在 P0 真实阅读链路上完成可多端日用的书架、详情、阅读设置、进度与错误恢复。**多端同步是首要设计目标**：书架、分类、进度、书签和非敏感设置通过 Worker API 读写，以 D1 为唯一权威来源。P1 与前移的 [P2](p2-sync.md) 共同交付，先证明两个客户端共享收藏和继续阅读，再完善全部外围 UI。

状态：**进行中，收藏与进度已切换到 Worker API + D1，测试身份下 Web↔iOS、Web↔Android、iOS↔Android 的基础书架读回与双向非默认页续读已通过**，见[Web/iOS 证据](../verification/native-server-state.md)和[Android 配对证据](../verification/android-server-state.md)。本地业务 SQLite、持久化依赖和数据库 Web 资产已移除；书架/进度共享服务端 revision 与确认路径。实际双 Web 的手动刷新、远端重置、旧视图停止写入/写冲突和明确重开已通过[分项](../verification/concurrent-server-state.md)；同时写竞争、自动前台重取、故障恢复、生产 Access、真机、Web↔Native 分类、Android 初始化可靠性、章节书签及范围已读/未读的独立客户端验收、阅读设置（含裁白）的剩余平台/漫画覆盖与故障门、自定义封面的独立客户端验收及完整日用流程仍待实施或验收，不能认定完整 P1 通过。

- 独立 Dart 阅读核心已有逻辑锚、布局/方向、缩放和有界资源调度；当前/最远位置、显式完成、重新阅读 epoch、保存失败提示和节流机制已有实现。Web 真实 Arknights 关标签页恢复及双端模拟器原 xkcd 进程重启的历史分项见[Web 产品进度](../verification/reader-progress-web.md)和[本地进度记录](../verification/local-progress.md)；这些结果保留原输入和范围。
- 单 hostname、Access/API、D1 网络策略工程入口与 Protobuf/Buf 控制协议已经存在。收藏、元数据、分章进度、resume 与幂等结果已建立 D1 表、双端生成业务协议和正式 API；工程和真实多端证据仍分别验收。

4. 详情章节名/扫描组/显示编号搜索、来源原序/反序、书签组合筛选和重复项说明已接入正式 UI，工程证据见[章节浏览](../verification/chapter-browsing.md)。范围已读/标未读已按[章节状态设计](../design/chapter-read-state.md)接入协议、现有进度表、数据层和正式详情 UI，支持状态筛选、隐藏选择与反序闭区间，逐章串行确认；不为标记操作请求每章 pages。真实 D1、数据和正式组件回归见[验证记录](../verification/chapter-read-state.md)，独立客户端读回仍待验。保留原 Source URL、稳定 ID、空/小数章节编号及来源顺序，不按标题全局去重。范围已读、标未读和重读也必须由服务端确认并在另一端读回。

6. **验收服务端逻辑锚与跨端阅读语义。** `chapterKey + pageKey + manifestVersion + pageIndexHint + normalizedOffset + normalizedX + viewportX + viewportY` 等逻辑锚已接到 D1，分开保存当前回看位置、同 epoch 最远进度和显式完成状态；继续验证跨端与并发行为，跨 manifest 不直接比较旧序号。复用现有 600 ms trailing debounce、2 秒最长等待和切章/退出/后台尽力提交机制，服务端返回确认才显示已保存。阅读器自然完成路径仍要求末页真实显示后，显式“读完本章”或“下一章”才标完成；详情中的人工标已读是独立明确操作，不伪造观察记录或末页锚。重新阅读由服务端原子提升 epoch，旧提交不能覆盖它。保持当前阅读位置，不因另一设备更新而强制跳页；不依赖 unload 一定成功，不生成时间线事件。
7. 完成网络错误、验证、Source 登录与 Access 失效的独立状态。API 的幂等业务重试与 Source 请求副作用分别处理；有限重试安全读取，取消无用请求，不盲目重发 Source POST。Web 更新前尽力提交位置并明确失败，阅读中不强制重载；身份/服务切换后旧草稿和迟到结果不能写入新身份。
8. 对实际候选 Source 必需的远程脚本提供局部适配、最小回调与超时/存储边界；未实现路径明确受限，不把同源 `eval` 称为受限沙箱。该工作不阻塞已经可读 Source 的基础多端功能实现。

## 下一功能里程碑

当前自定义封面的集中工程检查与独立客户端门分别记录。本轮按功能完整性优先补齐以下两项日用入口，状态为已实现、待独立客户端验收：

- **书架直接续读（已实现，待独立客户端验收）**：把服务端已确认的 `MangaState.resume` 投影到书架，在保留详情入口的同时提供明确续读操作；取得当前 Source 和章节清单后按稳定 chapterKey 解析，复用正式 Reader 路由，章节缺失时明确回到详情，不另建本地进度权威。
- **详情失败恢复（已实现，待独立客户端验收）**：开章遇普通 Source 错误时保留本次选择，在当前详情给出专用提示并允许显式重试；续读位置读取失败提供只读重取入口，不自动重放 Source 副作用或未确认进度写入。已实现的 Access 暂停/认证恢复继续验收；候选 Source 的验证或登录能力先确认实际需求，再做最小适配。

续读区分已确认记录与当前会话未保存草稿；无草稿时由正式 Reader 的最后一次章节状态读取决定位置和顺序。详情开章失败即时提示并保留同章重试，续读读取有独立只读重取入口。附带资料更新不能隐式重放其它 pending；元数据丢响应后有专用原请求重试，ACK 成功与后续刷新失败分别显示。设计见[阅读入口](../design/reading-entry.md)，集中检查、已修复问题与剩余独立客户端/生产/设备门见[验证记录](../verification/reading-entry.md)。[P3 的收藏源与快捷打开里程碑](p3-extensions-and-migration.md#收藏源里程碑)也已实现待独立客户端验收，后续按统一计划继续补齐功能；实际 Source 验证/登录需求以候选源事实为依据。

## 验收

- 同一部署与身份在 Web、iOS、Android 通过相同 Worker API 共享收藏、分类、书签、设置和阅读位置；至少两个独立客户端实际读写确认，具体平台组合和并发矩阵见 [P2](p2-sync.md)。服务端已确认状态在新客户端和重启后从 D1 恢复。
- “A 端收藏 → B 端书架 → 详情取章 → 完整阅读 → 服务端确认进度 → A 端继续阅读”形成日用闭环；当前/最远进度、epoch、删除与设置冲突有明确结果。只在单端恢复或只通过 SQLite 测试不能通过本项。
- 网络失败可重试、取消和恢复，不串身份或结果；云端请求失败仍可阅读已经加载的页面，UI 准确区分未保存与已确认状态。Source 文件/cache、扩展缓存、图片资源与业务状态归属明确分开。
- 手机触控、桌面键盘、平板分屏和阅读更新恢复通过实际环境验证；裁白/布局改变后仍定位同一原图锚点。
- Access 登录不成为应用内账号模块；不引入自动更新、离线下载、持久离线操作队列、历史统计、tracker、本地漫画或备份。

完整 P1 必须包含 P2 的基本多端状态门；增量日志、cursor、DO 通知等优化在实测需要后另行安排，不以这些优化延后基础跨端交付。
