# P1 书架、阅读设置与进度

## 目标与状态

在 P0 真实阅读链路上完成可日用的书架、详情、阅读设置、进度与错误恢复。状态：**未开始完整产品实施**；现有资料浏览、阅读核心和 UI 外壳是基础，不能视为书架或进度持久化已完成。

## 已有基础

- Flutter 浏览支持构建/Source 选择、热门/最新/搜索分页、详情和章节入口。
- 独立 Dart 阅读核心已有稳定逻辑锚、布局/方向、缩放和有界资源调度；实际图片接入仍属于 [P0](p0-runtime-and-reading.md)。
- 单 hostname、Access/API、D1/R2 工程入口已存在；书架/进度业务表、客户端镜像和 repository 尚未建立。

## 待办

1. 设计并迁移漫画、收藏、章节、分类、多分类关联、进度/书签/阅读位置和阅读设置；D1 保存云端业务状态，客户端维护当前身份镜像与待提交变更。Flutter 平台的具体存储适配需落实，不能照搬历史 React/Dexie 代码结构。
2. 完成收藏、分类排序、书架搜索/过滤/批量操作、自定义封面及继续阅读。未读数只使用已主动取得的章节列表，不触发全书架查更新。
3. 完善详情章节搜索/排序/筛选、重复章节展示、范围已读操作；保留原 Source URL、稳定 ID、空/小数章节编号和来源顺序，不按标题全局去重。
4. 完善全局与漫画覆盖阅读设置：分页/连续/Webtoon、单双页、方向、适宽/适高、裁白、背景/应用内亮度、点击区与键盘；能力不足时保留正常阅读。
5. 将 `chapterKey + pageKey + manifestVersion + normalizedOffset` 等逻辑锚持久化；分开保存当前回看位置与最远进度。节流落盘，切章/退出尽力提交，不依赖 unload 成功，不生成时间线事件。
6. 完成网络错误、验证、Source 登录和 Access 失效的独立状态；有限重试安全读取，取消无用请求，不盲目重发副作用 POST。Web 更新先保存位置，阅读中不强制重载。
7. 对实际候选 Source 必需的远程脚本提供局部适配、最小回调与超时/存储边界；未实现路径明确受限，不把同源 `eval` 称为受限沙箱。

## 验收

- 收藏、分类、设置、书签和阅读位置在客户端/容器重启后恢复；同一身份存储与 Source 文件/cache 明确分离。
- 从书架继续阅读、详情取章、完整阅读到进度保存形成日用闭环；网络失败可重试、取消和恢复不串结果。
- 手机触控、桌面键盘、平板分屏和阅读更新恢复通过实际环境验证；裁白/布局改变后仍定位同一原图锚点。
- Access 登录不成为应用内账号模块；不引入自动更新、离线下载、历史统计、tracker、本地漫画或备份。

多设备并发与断网合并由 [P2](p2-sync.md) 验收；P1 不提前宣称同步完成。
