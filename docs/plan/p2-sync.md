# P2 基本多设备同步

## 目标与状态

同步同一部署、同一身份的书架、分类、基本阅读进度、书签和非敏感设置。状态：**未开始实现**；同步语义已有设计，当前构建注册表、鉴权与通知类不等于同步业务已存在。依赖 [P1](p1-library-and-progress.md) 的状态模型和 [P0](p0-runtime-and-reading.md) 的真实会话恢复。

## 已确定的边界

- D1 的幂等变更和增量日志是云端真相；客户端先写本地状态/outbox，再 push/pull。DO 只提示“有更新”或协调会话，不承载漫画正文，不取代持久增量。
- 同步保存当前状态，不生成用户阅读历史、时长或统计事件；不传图片、下载任务、源站密码/token/cookie。
- 当前回看位置与最远进度分开；设备时钟不能单独决定冲突结果。外部 64 位 ID 使用字符串，保守处理 Source URL。

## 待办

1. 加入客户端 ID、幂等 mutation ID、单调服务端 revision、删除墓碑和有限期 change log；使用 D1 支持的 batch/条件 SQL/唯一约束，明确事务边界。
2. 实现有界批次 push、cursor 分页 pull、本地 outbox 重试与去重；Access 失效暂停提交，恢复同一身份后继续，不清空未提交状态。
3. 同一阅读 epoch 的普通进度只前进；“标未读/重读”显式提升 epoch，旧离线进度不能覆盖新 reset。两个离线 reset 使用确认或确定性服务端规则。
4. 分类、设置等按字段 revision 或操作合并；删除墓碑防止旧设备复活数据。超过增量保留期的设备明确全量重同步。
5. 加入断网、重复提交、乱序、双设备并发、游标过期、D1/DO 重启和 Access 恢复回归；通知丢失时依然能靠 pull 收敛。

## 验收

- 两设备同时修改、短暂断网后上线或重复提交后收敛；已读进度不被旧页码倒退，reset 不被旧 epoch 覆盖。
- 本地提交与确认具有可追踪幂等身份；游标分页不漏不重，删除不复活，长离线明确重同步。
- DO/容器重启不串回调或身份，通知失败不丢业务状态；云端故障不阻断当前本地阅读。
- 同步不扩展为离线阅读、后台任务、历史事件、文件归档或敏感凭证同步。
