## 当前交付顺序

1. 完成收藏和非默认页续读的三端实际配对，记录 Web↔iOS、Web↔Android、iOS↔Android 的双向读写与服务端确认；测试身份、生产 Access、模拟器与真机分别验收。
2. 验收实际双客户端并发、响应丢失后的幂等重试、前台重取与断网恢复，确认冲突不覆盖另一端状态、最远进度不倒退、旧 epoch 不覆盖重新阅读。
3. 按分类 → 书签 → 非敏感设置逐项交付，从 Protobuf 合同、D1 原子读写到 Flutter UI 一起完成；每项从协议、D1 到正式 UI 共同实现；优先补齐功能，再集中取得独立客户端读回证据，未验收的项目保持明确待办。
4. 阅读设置（含外观与输入预设）已接入正式 UI，工程范围见[设置记录](../verification/reader-appearance.md)；详情章节搜索/原序反序/书签组合筛选也已实现，见[章节浏览](../verification/chapter-browsing.md)；书架多选、批量添加/移出分类及移出书架已接入，见[批量操作设计](../design/library-batch.md)；章节范围已读/标未读已接入正式协议、D1 和详情 UI，见[章节状态记录](../verification/chapter-read-state.md)，独立客户端门待验；完整显示/适宽/适高及二维原图锚已接入，见[适配记录](../verification/reader-fit.md)；裁白已接入全局/漫画继承与覆盖，并在服务端确认后应用到正式 Reader，显式 false 与缺省继承区分，独立客户端验收仍待完成，见[裁白记录](../verification/reader-crop.md)；下一项功能为自定义封面，再依据目标设备实测安排性能优化。生产 Access 和真机的 P0 基础验收并行推进，不因等待这些环境而停下可独立完成的同步功能。

每个功能里程碑先完成实现，再进行有意义的集中验证；详细待办与验收条件以 [P2](p2-sync.md) 为准。

## 维护约定

- 状态使用“未开始、进行中、已实现待验收、已验收、讨论待定”，只有对应验收证据成立才标为已验收。
- 实现变化更新所属计划；影响优先级或依赖时再更新本索引。详细证据保留实际平台、浏览器和执行环境，历史 Safari 验证不能改称 Codex 内置浏览器验证。
- 未来浏览器交互按 [AGENTS](../../AGENTS.md) 使用 Codex 内置浏览器；历史证据保持原环境。
- [设计依据](../PLAN.md#设计依据)保留来源和决策背景，并随新决策更新。`docs/design/` 已解除冻结；当前计划沿用已确定的 Flutter + TeaVM 架构。
- 暂缓模块不预建页面、表或接口：自动/批量更新、离线下载、历史统计、tracker、本地漫画、备份恢复、应用内账号与隐私模块。
