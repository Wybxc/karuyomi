# 本机设置、自动保存、自适应布局与漫画封面

2026-11-21，用户要求区分本机与远程设置、改成自动保存、为宽窄窗口设计 Cupertino 布局，并接入普通漫画封面的获取与显示。四项改动沿用 Web、iOS、Android 的共享 Flutter 客户端和既有 Source 宿主。已上线的界面对照是本轮基线。[生产基线](https://github.com/Wybxc/karuyomi/pull/8)

## 现状与选择

| 事项           | 已核对的实现                                                                                       | 本轮取向                                                                          |
| -------------- | -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 设置归属       | 应用主题、阅读默认值和作品覆盖在账户设置协议中。原生服务地址已经用 `SharedPreferencesAsync` 保存。 | 外观与设备输入由本机持久化，账户资源及跨端阅读偏好继续由 Worker API + D1 确认。   |
| 自动保存       | 全局和单漫画编辑器保留带 revision 的草稿，常规编辑由保存按钮提交。阅读快捷项已经有直接提交的路径。 | 普通有效编辑触发保存。复用现有确认、冲突和精确重试流程。                          |
| Cupertino 布局 | 主壳使用底部标签，设置已有双栏和紧凑导航。官方 `cupertino_ui 1.1.6` 提供所需导航和控件。           | 用 Flutter 约束选择布局，复用一套选择状态、导航和业务控制器。                     |
| 漫画封面       | Source DTO 已保留 `thumbnailUrl`，列表已有封面格和占位，自定义封面有私有字节通道。                 | 用原 Source 的客户端取封面，向 Flutter 交付有界编码字节，沿用自定义封面的优先级。 |

宽窄按窗口和父级布局约束决定，兼顾分屏、横屏和大字号。布局采用官方 Flutter 的 `LayoutBuilder`、`SafeArea` 和标签、列表、路由等 Cupertino 控件。本机非关键偏好沿用现有 `SharedPreferencesAsync`。[Flutter 自适应指南](https://docs.flutter.dev/ui/adaptive-responsive/general) · [Cupertino UI](https://pub.dev/packages/cupertino_ui/versions/1.1.6) · [本机偏好存储](https://pub.dev/packages/shared_preferences/versions/2.5.6)

## 1. 设置归属

| 本机设置                                                                 | 账户设置                                                                                 |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| 应用外观，含跟随系统、浅色和深色。阅读画布背景、调暗、触控区和键盘预设。 | 默认及单漫画的阅读模式、单双页意图、图像适配和裁白。书架、分类、阅读进度、书签仍属账户。 |
| 原生服务地址。已有的单漫画显示和输入覆盖在本机继续支持继承。             | 收藏源、扩展安装选择、仓库以及已获同步许可的 Source 设置。                               |

本机外观在连接和登录前可用，切换账号不改外观。Web 一份浏览器资料下的同源文档共用本机偏好，换浏览器资料或设备各自独立。阅读器以当前设备显示、输入偏好和服务端已确认的阅读偏好组成有效配置，保留当前页与图像锚。单漫画的本机覆盖按部署和作品身份隔离，空覆盖继承本机默认。Source 凭证和未审核值仍服从其会话隔离策略。[现有阅读设置](../design/reader-settings.md) · [Source 偏好边界](../design/source-preferences.md)

- [x] 将应用主题从账户设置移到本机。客户端、ProtoJSON、验证器和默认值同步更新。隔离 D1 验证旧文档规范化后仍能读回阅读偏好、版本与原单漫画回执。新设备从系统主题起步。
- [ ] 将阅读画布与输入项移到本机，保留逐漫画的选择和继承。分离设备设置入口与账户连接，应用实际页面继续使用同一组有效阅读配置。
- [ ] 验收本机外观离线生效并在重开后恢复。同一账号的两个独立浏览器资料分别保留浅色和深色，本机编辑零账户写入。另核对阅读偏好仍可从另一个已登录客户端读回。

## 2. 设置自动保存

点选、开关在有效修改后提交，滑杆和文字使用完成输入或合并后的最后有效值。页面初始化、重取服务端值、切换宽度及关闭并重开设置只读取确认状态。设备写入失败时保留可恢复的选择并提示。本机服务地址和需要确认的 Source 动作保留明确的连接或执行入口。插件偏好依旧经原 listener 执行一次。

- [ ] 本机设置改为选择即保存，复用同一个选项组件，提供保存中和失败反馈。主题已接通，阅读画布与输入待接入。
- [ ] 在现有 `SettingsController` 和业务接口上完成全局及单漫画设置自动保存。同一作用域串行提交，合并其余未发送的同域修改。只有有效 ACK 才更新应用侧已确认值。版本冲突先读回并让用户决定，未知结果重试原 UUID、正文及 CAS，已确认待读取仅重读。
- [ ] 将普通可编辑 Source 设置接入相同行为，保持已有同步许可、受保护输入与 listener 的处理语义。切换服务或账号取消待发送修改，迟到的结果按原身份隔离。
- [ ] 验收快速修改、退出再开、跨设备竞争、回执丢失、登录失效和失败恢复。编辑期间可以继续读已加载内容，未确认状态可见，未确认草稿只保留在当前会话。

## 3. 窄屏、中宽与宽屏

| 可用空间 | 导航与内容                                                                               |
| -------- | ---------------------------------------------------------------------------------------- |
| 紧凑窗口 | 底部标签和单栏主页面。详情、选项和设置分组通过 Cupertino 路由进入，返回原列表位置。      |
| 中宽窗口 | 空间足够时显示侧栏和单内容区。平板分屏或较大文字缩窄内容时可以回到单栏。                 |
| 宽窗口   | 维持侧栏。设置和适合并读的书架、浏览列表提供列表与详情双栏。阅读页保留独立画布和阅读锚。 |

- [ ] 从既有主壳及设置双栏收敛窗口布局，按内容所需最小宽度选择主导航和第二栏。保持当前标签、源及查询、打开的详情、设置分组、焦点和阅读锚。
- [ ] 将书架和浏览的相关列表详情接入同一模式选择，由实际空间确定格列数、详情宽度和安全区。使用已锁定的 Cupertino 控件与路由。
- [ ] 验收手机竖屏和短横屏、平板分屏、平板常规宽度及桌面拖窄窗口。浅深色与双倍字号验证键盘返回、焦点、长文本和控件可达。宽窄切换不产生业务写入。

## 4. Source 封面

普通封面走当前 Source 绑定的图片读取。Mihon 封面读取使用 `HttpSource` 自己的客户端和请求头，Karuyomi 在宿主保持同类访问语义，继续利用原 Source 的请求头、Cookie 和拦截器。已经确认的自定义封面优先。Flutter 负责识别、解码、显示和失败占位，封面不会更改用户的漫画记录。[Mihon 封面读取](https://github.com/mihonapp/mihon/blob/feadad5e1e2bf638be6e2ca317d11657b09d4596/app/src/main/java/eu/kanade/tachiyomi/data/coil/MangaCoverFetcher.kt) · [自定义封面](../design/custom-covers.md)

- [ ] 先接通单源列表和作品详情。按当前构建、Source 与作品身份调用宿主，复用小控制消息、受管二进制资源和释放路径。限制同时请求、字节和等待时间，滚离视口、来源切换或 generation 改变后取消并丢弃迟到结果。
- [ ] 用有封面的代表 Source 取得真实图片，并核对原客户端的请求行为。如果宿主入口需要重编扩展，先交付少量代表包并按既有 AOT 与 Static Assets 流程验收。
- [ ] 将普通封面接入跨源结果、书架和迁移候选，按可见范围复用既有有界 Source 执行。封面读取保持活动阅读和搜索的会话身份。稳定格子比例，失败时保留可操作的占位。
- [ ] 验收真实封面缺失、断网、源和构建变化、迟到释放、自定义封面优先和清除后的恢复。确认没有通过浏览器直接访问未经 Source 处理的图片地址。

## 交付顺序

先拆分应用主题和普通保存事件，再完成账户自动保存与本机阅读显示/输入。然后收敛宽窄壳和双栏，自适应列表上接入普通封面。每个阶段按实际改动提交、推送并记录验证。全量构建交给 CI，内置浏览器复验关键真实流程，原生现场验收按已有用户授权执行。目标完成条件为四项在正式入口有实现与相应环境的可复验证据。
